# 3. Cloudflare hosting, Effect confined to the core

Date: 2026-11-04

## Status

Accepted

## Context

This is a personal app for two people. It must cost nothing to run, deploy from `main` with no ceremony, and stay maintainable by one person with agent help. The sync server is small: accept pushed events, serve pulls by cursor, hash the two secret links. The frontend is a mobile-first PWA that must also work on a Mac for configuration.

## Decision

**Hosting: Cloudflare.** `apps/web` (Vite + React + TypeScript strict + Tailwind, PWA) deploys to Cloudflare Pages; `apps/api` (Hono on Cloudflare Workers) stores the journal in D1. Both are on the free tier and deploy from `main`. Access is through two secret links generated by the household (secret in the URL fragment, hashed server-side, regenerable); no accounts, no push notifications in v1.

**Effect, confined to the core.** `packages/domain` (events, reducer, the `EventStore` / `SyncTransport` / `Clock` ports) and `packages/wire` (the shared Effect Schema contract between web and API) use Effect. React components never see Effect: they consume plain state and call plain functions. Both packages are source-only, bundled by their consumers.

**Monorepo**: pnpm workspace + Turborepo + Biome + lefthook, following Choravo's conventions. One fast `pnpm check` (Biome + typecheck + Vitest) runs locally on every commit and in CI.

## Consequences

- Zero hosting cost and a deploy that is a push to `main`.
- Workers constrain the server to the fetch handler model and D1 to SQLite semantics; both fit an append-only journal.
- Effect gives typed errors, services for the ports and a single Schema for both ends of the wire, without leaking into rendering code where it would hurt readability and bundle size.
- Two Effect-aware packages to keep in sync with the apps; the wire contract is the seam that keeps them honest.

## Alternatives rejected

- **Convex** as backend: no local persistence and an archived offline engine (see ADR 2).
- **Fly.io** with a small Node or Elixir server: works (Choravo runs there), but it is not free at rest and needs an image and a database to operate. Kept as **plan B** if Workers or D1 get in the way.
- **Effect everywhere, including React**: consistent, but every component would carry Effect runtime plumbing and the UI would be harder to read and to hand to a design pass.
- **No Effect at all**: possible for a project this size, but the ports, typed errors and shared Schema are exactly the parts that benefit, and the cost is contained to two packages.
